# Nigerian Network Detector

Detects which Nigerian mobile network (MTN, Glo, Airtel, 9mobile) a phone
number's prefix was **originally allocated to**.

> **Important:** this tells you the *original* network, not necessarily
> the *current* one. Nigeria has Mobile Number Portability (MNP) — a
> subscriber can keep their number after switching carriers. A number
> starting `0905` was originally allocated to Glo, but may have since
> been ported elsewhere. This project never claims otherwise: every
> response is explicitly labeled `"detection_type": "prefix"`, and
> `current_network` / `ported` are always `null` since no real-time
> carrier/MNP lookup is wired in.

## Stack

- **Backend:** Python 3.10+, FastAPI, Pydantic, Jinja2, served by Uvicorn
- **Frontend:** plain HTML/CSS/JS — no build step. JS only animates the
  existing markup (a pop-in on the result card); it does no detection of
  its own and never restructures the page.
- **Tests:** pytest, via FastAPI's `TestClient`

without pulling in a web server.

## Getting started

Requires Python 3.10+.

```bash
cd nigerian-network-detector
pip install -e ".[dev]"
python main.py
```

Then open **http://127.0.0.1:8000**.

By default the server runs with auto-reload enabled. Configure it with
environment variables if needed:

| Variable | Default     | Purpose                        |
|----------|-------------|---------------------------------|
| `HOST`   | `127.0.0.1` | Bind address                   |
| `PORT`   | `8000`      | Bind port                      |
| `RELOAD` | `true`      | Auto-reload on file changes    |

```bash
PORT=9000 RELOAD=false python main.py
```

Once installed, you can also run it as a console script or module:

```bash
nigeria-network-detector
# or
python -m nigeria_network_detector
```

## Running tests

```bash
pytest
```

- `tests/test_detector.py` — unit tests for normalization and prefix
  matching: all accepted input formats, invalid numbers, empty input,
  overlong input, letters, special characters, unsupported prefixes.
- `tests/test_app.py` — integration tests for the HTTP layer: the
  homepage, `/health`, `/version`, and every status code the phone-check
  endpoint can return.

A failing test prints the assertion and a diff of expected vs. actual —
run `pytest -v` for per-test output, or `pytest -k name` to run a subset
matching `name`.

## API reference

### `GET /api/v1/phone/{phone_number}`

Accepts `0905000...`, `+234905000...`, `234905000...`, with spaces,
dashes, or parentheses — all normalized to one canonical form.

```
GET /api/v1/phone/09050003328
```

```json
{
  "phone_number": "+2349050003328",
  "country": "NG",
  "valid": true,
  "prefix": "0905",
  "original_network": {
    "slug": "glo",
    "name": "Glo Mobile",
    "color": "#0C8A3E",
    "textColor": "#FFFFFF"
  },
  "current_network": null,
  "ported": null,
  "detection_type": "prefix"
}
```

| Status | Meaning                                              |
|--------|-------------------------------------------------------|
| `200`  | Valid number, prefix matched to a known provider       |
| `404`  | Valid-looking number, but its prefix isn't in the table |
| `422`  | Not a valid Nigerian mobile number (empty, wrong length, non-numeric, etc.) |

Error responses always look like:

```json
{ "error": { "code": "INVALID_PHONE_NUMBER", "message": "..." } }
```

### `GET /api/v1/health`

```json
{ "status": "ok" }
```

### `GET /api/v1/version`

```json
{ "version": "0.1.0" }
```

Interactive OpenAPI/Swagger docs are auto-generated by FastAPI at
**`/docs`**.

## About the prefix data

`detector.py` ships a small demo prefix table covering the sample ranges
shown on the homepage — it is explicitly **not** sourced from an
authoritative NCC (Nigerian Communications Commission) dataset. Before
using this for anything real:

- Replace `_PREFIX_TABLE` / `PROVIDERS` in `detector.py` with data backed
  by a verified, current NCC allocation list — prefixes are reallocated
  over time, so this shouldn't be hardcoded in source at all long-term
  (a `providers` + `phone_prefixes` database table pair, updatable
  without a code deploy, is the right shape for that).
- If you need to know a number's *current* carrier (not just its
  original allocation), that requires a real MNP/carrier-lookup API —
  this project doesn't integrate one, and intentionally never implies
  it does.

## Architecture notes

- **routes → detector, not the other way around.** Routes only translate
  HTTP into Python calls and Python results back into HTTP — all the
  actual rules live in `detector.py`, which doesn't know FastAPI exists.
  That split is what makes `detector.py` trivial to unit test and
  `routes.py` trivial to read.
- **`create_app()` is a factory, not a module-level instance**, so tests
  can construct a fresh app with no import-time side effects.
- **JS is presentation-only.** `script.js` calls the API and toggles a
  CSS class to animate the result card in; it holds no phone-number
  logic of its own, by design — if the detection rules ever change,
  there's exactly one place to change them.
